### 🔴 Что нужно добавить (реальные юзер-кейсы)

#### 1. Поведение пользователя при ошибках

**1.1. Множественные быстрые клики по кнопке "Войти"**
- **Сценарий**: Пользователь быстро кликает 5-10 раз по кнопке входа
- **Ожидаемое поведение**: Должна быть защита от двойной отправки формы
- **Что может сломаться**: Множественные запросы, дублирование сессий, race conditions

**1.2. Изменение данных во время отправки формы**
- **Сценарий**: Пользователь вводит email, начинает вводить пароль, но пока форма отправляется, меняет email
- **Ожидаемое поведение**: Форма должна использовать актуальные данные или блокировать изменения
- **Что может сломаться**: Отправка устаревших данных, конфликты состояния

**1.3. Закрытие/обновление страницы во время авторизации**
- **Сценарий**: Пользователь нажимает "Войти" и сразу закрывает вкладку или обновляет страницу
- **Ожидаемое поведение**: Запрос должен корректно обрабатываться или отменяться
- **Что может сломаться**: Висящие сессии, утечки памяти, некорректное состояние на сервере

**1.4. Нажатие Enter vs клик по кнопке**
- **Сценарий**: Пользователь вводит данные и нажимает Enter вместо клика по кнопке
- **Ожидаемое поведение**: Оба способа должны работать одинаково
- **Что может сломаться**: Разное поведение, двойная отправка формы

#### 2. Граничные случаи ввода

**2.1. Копирование-вставка больших объемов текста**
- **Сценарий**: Пользователь копирует большой текст (10KB+) и вставляет в поля
- **Ожидаемое поведение**: Поле должно обрезать или валидировать длину
- **Что может сломаться**: Переполнение буфера, зависание UI, проблемы с производительностью

**2.2. Специальные символы в email (реальные случаи)**
- **Сценарий**: Email с плюсами, точками, дефисами в разных местах
  - `user+tag@example.com`
  - `user.name+tag@example.com`
  - `user_name@example.co.uk`
  - `"user name"@example.com` (с пробелами в кавычках)
  - `user@[192.168.1.1]` (IP адрес вместо домена)
- **Ожидаемое поведение**: Валидация должна корректно обрабатывать все валидные форматы
- **Что может сломаться**: Неправильная валидация, отказ в доступе легитимным пользователям

**2.3. Пароли с крайними значениями**
- **Сценарий**: 
  - Минимальная длина (если есть ограничение)
  - Максимальная длина
  - Только пробелы
  - Только спецсимволы
  - Только цифры
  - Только буквы
  - Кириллица в пароле
  - Пароль = email
- **Ожидаемое поведение**: Валидация должна быть последовательной
- **Что может сломаться**: Непоследовательная валидация, проблемы с кодировкой

**2.4. Пустые значения после пробелов**
- **Сценарий**: Пользователь вводит пробелы в начале/конце email или пароля
- **Ожидаемое поведение**: Trim должен работать или показывать ошибку
- **Что может сломаться**: Неожиданная авторизация, проблемы с валидацией

#### 3. Работа с формой и состоянием

**3.1. Автозаполнение браузера**
- **Сценарий**: Браузер предлагает сохранить/автозаполнить данные
- **Ожидаемое поведение**: Автозаполнение должно работать корректно
- **Что может сломаться**: Конфликты с валидацией, проблемы с remember me

**3.2. Сохранение пароля в браузере**
- **Сценарий**: Пользователь сохраняет пароль, затем пытается войти с измененным паролем
- **Ожидаемое поведение**: Браузер должен использовать актуальные данные
- **Что может сломаться**: Использование устаревших данных

**3.3. Чекбокс "Запомнить меня"**
- **Сценарий**: 
  - Включить/выключить несколько раз перед отправкой
  - Клик по чекбоксу во время отправки формы
  - Состояние чекбокса после ошибки авторизации
- **Ожидаемое поведение**: Состояние должно сохраняться корректно
- **Что может сломаться**: Некорректное сохранение состояния, проблемы с cookies

**3.4. Фокус и blur события**
- **Сценарий**: Пользователь быстро переключается между полями (Tab, клики)
- **Ожидаемое поведение**: Валидация не должна мешать навигации
- **Что может сломаться**: Потеря фокуса, проблемы с валидацией в реальном времени

#### 4. Сетевые и таймауты

**4.1. Медленное соединение**
- **Сценарий**: Авторизация на медленном соединении (throttling)
- **Ожидаемое поведение**: Должны быть индикаторы загрузки, возможность отмены
- **Что может сломаться**: Нет обратной связи, пользователь думает что зависло

**4.2. Прерывание соединения**
- **Сценарий**: Сеть обрывается во время авторизации
- **Ожидаемое поведение**: Должна быть обработка ошибки сети
- **Что может сломаться**: Висящее состояние загрузки, некорректные сообщения об ошибках

**4.3. Таймаут сессии**
- **Сценарий**: Пользователь открывает форму, ждет 30+ минут, затем пытается войти
- **Ожидаемое поведение**: Сессия должна обновиться или показать ошибку
- **Что может сломаться**: Использование устаревшей сессии, CSRF проблемы

**4.4. Одновременные запросы**
- **Сценарий**: Открыть форму в нескольких вкладках, попытаться войти одновременно
- **Ожидаемое поведение**: Каждая вкладка должна работать независимо
- **Что может сломаться**: Конфликты сессий, проблемы с токенами

#### 5. UI/UX проблемы

**5.1. Изменение размера окна**
- **Сценарий**: Пользователь изменяет размер окна во время ввода данных
- **Ожидаемое поведение**: Форма должна оставаться функциональной
- **Что может сломаться**: Потеря данных, проблемы с layout

**5.2. Zoom браузера**
- **Сценарий**: Увеличение/уменьшение масштаба (50%, 200%)
- **Ожидаемое поведение**: Форма должна быть читаемой и функциональной
- **Что может сломаться**: Наложение элементов, проблемы с кликами

**5.3. Мобильное устройство (если применимо)**
- **Сценарий**: Авторизация на мобильном устройстве
- **Ожидаемое поведение**: Форма должна быть удобной для мобильных
- **Что может сломаться**: Проблемы с клавиатурой, автозаполнением, touch событиями

**5.4. Скроллинг во время авторизации**
- **Сценарий**: Пользователь скроллит страницу во время отправки формы
- **Ожидаемое поведение**: Сообщения об ошибках должны быть видны
- **Что может сломаться**: Потеря важных сообщений, плохой UX

#### 6. Браузерные особенности

**6.1. Разные браузеры**
- **Сценарий**: Тестирование в Chrome, Firefox, Safari, Edge
- **Ожидаемое поведение**: Единообразное поведение
- **Что может сломаться**: Различия в обработке событий, валидации

**6.2. Режим инкогнито**
- **Сценарий**: Авторизация в режиме инкогнито
- **Ожидаемое поведение**: Должна работать так же как в обычном режиме
- **Что может сломаться**: Проблемы с cookies, localStorage

**6.3. Блокировщики рекламы**
- **Сценарий**: Авторизация с включенным блокировщиком (uBlock, AdBlock)
- **Ожидаемое поведение**: Не должно влиять на функциональность
- **Что может сломаться**: Блокировка важных скриптов, проблемы с загрузкой

**6.4. Отключенный JavaScript**
- **Сценарий**: Попытка авторизации с отключенным JS
- **Ожидаемое поведение**: Должна быть graceful degradation или сообщение
- **Что может сломаться**: Полная неработоспособность формы

#### 7. Восстановление пароля

**7.1. Множественные запросы на восстановление**
- **Сценарий**: Пользователь запрашивает восстановление пароля 10 раз подряд
- **Ожидаемое поведение**: Должна быть защита от спама
- **Что может сломаться**: Спам в почте, проблемы с производительностью

**7.2. Несуществующий email**
- **Сценарий**: Запрос восстановления для несуществующего email
- **Ожидаемое поведение**: Не должно раскрывать информацию о существовании аккаунта
- **Что может сломаться**: Информационная утечка (enumeration attack)

**7.3. Истечение токена восстановления**
- **Сценарий**: Использование старого токена восстановления
- **Ожидаемое поведение**: Должна быть ошибка с понятным сообщением
- **Что может сломаться**: Некорректная обработка, проблемы безопасности

#### 8. Интеграции и зависимости

**8.1. Отключенные внешние сервисы**
- **Сценарий**: Если форма зависит от внешних API (капча, OAuth), что если они недоступны?
- **Ожидаемое поведение**: Должна быть обработка ошибок
- **Что может сломаться**: Полная неработоспособность формы

**8.2. Медленные внешние сервисы**
- **Сценарий**: Внешний сервис отвечает очень медленно
- **Ожидаемое поведение**: Должны быть таймауты и fallback
- **Что может сломаться**: Долгое ожидание, плохой UX

- ✅ Форма не ломается визуально
- ✅ Нет JavaScript ошибок в консоли
- ✅ Нет утечек памяти
- ✅ Корректные сообщения об ошибках
- ✅ Нет проблем с производительностью
- ✅ Нет проблем с безопасностью
- ✅ Логи на сервере не засоряются ошибками
