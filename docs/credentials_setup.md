# Настройка учетных данных для тестов

## Восстановление кредов

Для работы тестов авторизации необходимо настроить учетные данные в файле `.env`.

### Шаг 1: Создание файла .env

Создайте файл `.env` в корне проекта на основе `.env.example`:

```bash
cp .env.example .env
```

### Шаг 2: Заполнение учетных данных

Откройте файл `.env` и заполните следующие переменные:

```env
# Тестовый пользователь (для основных тестов авторизации)
TEST_USER_EMAIL=ваш_email@example.com
TEST_USER_PASSWORD=ваш_пароль

# Оператор (для тестов телефонии)
TEST_OPERATOR_EMAIL=operator@example.com
TEST_OPERATOR_PASSWORD=пароль_оператора

# API ключ
LINER_API_KEY=ваш_api_ключ
```

### Шаг 3: Проверка конфигурации

Убедитесь, что в `config/config.json` указаны правильные плейсхолдеры:

```json
{
  "credentials": {
    "valid_user": {
      "email": "${TEST_USER_EMAIL}",
      "password": "${TEST_USER_PASSWORD}"
    },
    "operator": {
      "email": "${TEST_OPERATOR_EMAIL}",
      "password": "${TEST_OPERATOR_PASSWORD}"
    }
  }
}
```

### Шаг 4: Проверка работы

Запустите тест авторизации для проверки:

```bash
pytest tests/test_auth.py::TestAuthentication::test_successful_login -v
```

## Где взять креды?

1. **Тестовый пользователь**: Обратитесь к администратору тестового окружения
2. **Оператор**: Креды для тестов телефонии обычно предоставляются отдельно
3. **API ключ**: Получите у администратора API или в настройках системы

## Безопасность

⚠️ **Важно:**
- Никогда не коммитьте файл `.env` в репозиторий
- Файл `.env` должен быть в `.gitignore`
- Не передавайте креды через незащищенные каналы связи
- Используйте разные креды для разных окружений (dev, staging, production)

## Переменные окружения в CI/CD

В CI/CD системах (GitHub Actions, GitLab CI и т.д.) настройте переменные окружения в настройках проекта:

- `TEST_USER_EMAIL`
- `TEST_USER_PASSWORD`
- `TEST_OPERATOR_EMAIL`
- `TEST_OPERATOR_PASSWORD`
- `LINER_API_KEY`

## Troubleshooting

### Ошибка: "Переменная окружения 'TEST_USER_EMAIL' не найдена"

**Решение:** Убедитесь, что:
1. Файл `.env` существует в корне проекта
2. Переменные указаны правильно (без пробелов вокруг `=`)
3. Используется `python-dotenv` для загрузки переменных

### Ошибка: "Авторизация не удалась"

**Решение:**
1. Проверьте правильность кредов
2. Убедитесь, что тестовое окружение доступно
3. Проверьте, что пользователь не заблокирован
4. Проверьте логи тестов для деталей ошибки

### Ошибка: "Форма авторизации не готова"

**Решение:**
1. Проверьте доступность тестового окружения
2. Убедитесь, что URL в `config/config.json` правильный
3. Проверьте, что страница авторизации загружается в браузере
